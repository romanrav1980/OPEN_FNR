# Техническое Задание На UI-Тестирование OPEN FNR

## 1. Назначение Документа

Документ описывает, какое UI-тестирование должно быть выполнено для бизнес-процессов системы OPEN FNR.

Тестирование должно проверять не только отображение экранов, но и прохождение бизнес-сценариев:

- от загрузки данных до публикации прогноза;
- от промо-плана до заказа под промо;
- от прогноза до order proposal;
- от исключения до решения пользователя;
- от ручной корректировки до audit trail;
- от fresh-риска до изменения заказа.

Связанные документы:

- [BUSINESS_PROCESS_DETAILED_SPEC.md](BUSINESS_PROCESS_DETAILED_SPEC.md)
- [BUSINESS_PROCESSES_UI_SPEC.md](BUSINESS_PROCESSES_UI_SPEC.md)
- [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md)

## 2. Цели UI-Тестирования

UI-тестирование должно подтвердить, что:

- пользователь может пройти каждый бизнес-процесс от начала до конца;
- обязательные поля контролируются;
- ошибки и исключения видны и понятны;
- ручные корректировки работают безопасно;
- массовые действия имеют preview и подтверждение;
- audit trail фиксирует все изменения;
- права доступа соблюдаются;
- данные на UI соответствуют API и расчетным витринам;
- интерфейс выдерживает большие таблицы и фильтры;
- ключевые экраны соответствуют UI SLA.

## 3. Типы UI-Тестов

| Тип теста | Назначение |
| --- | --- |
| Smoke UI | проверка открытия ключевых экранов |
| Functional UI | проверка бизнес-функций |
| E2E UI | сквозной пользовательский сценарий |
| Validation UI | проверка обязательных полей и ошибок |
| RBAC UI | проверка прав доступа |
| Audit UI | проверка журнала изменений |
| Regression UI | защита от повторных дефектов |
| Performance UI | скорость открытия, фильтрации, массовых действий |
| Accessibility | клавиатура, фокус, контраст, читаемость |
| Visual regression | стабильность верстки и графиков |

## 4. Тестовые Роли

| Роль | Что проверяется |
| --- | --- |

| Fresh Manager | срок годности, списания, fresh-заказы |
| Category Manager | категория, ассортимент, промо, жизненный цикл |

## 5. Тестовые Данные

Для UI-тестов должны быть подготовлены тестовые наборы:

| Набор | Описание |
| --- | --- |
| Regular demand | стабильный SKU без промо |
| Promo valid | промо со всеми обязательными полями |
| Promo incomplete | промо без цены, скидки, выкладки или SKU |
| Promo conflict | пересекающиеся промо |
| Stock-out | товар без остатка при ненулевом спросе |
| Overstock | избыточный запас |
| Fresh risk | товар с коротким сроком годности |
| New SKU | SKU без истории продаж |
| Phase-out SKU | товар с termination date |
| DC shortage | РЦ не покрывает потребность магазинов |
| Supplier constraint | MOQ/MOV/cutoff блокирует заказ |
| Manual adjustment | корректировка прогноза и заказа |
| Export failure | ошибка публикации в ERP/WMS |

## 6. Общие Проверки Для Всех Экранов

| Проверка | Ожидаемый результат |
| --- | --- |
| Открытие экрана | экран открывается без ошибок |
| Loading state | показывается состояние загрузки |
| Empty state | пустой результат объяснен пользователю |
| Error state | ошибка API показана понятно |
| Фильтры | фильтры применяются и сбрасываются |
| Сортировка | таблицы сортируются корректно |
| Пагинация | страницы переключаются без потери фильтров |
| Закрепленные колонки | ключевые колонки остаются видимыми |
| Экспорт | большой экспорт запускается асинхронно |
| Права | недоступные действия скрыты или disabled |
| Audit | изменения видны в истории |
| Навигация | drill-down сохраняет контекст |
| URL state | фильтры можно открыть по ссылке |

- отсутствующие остатки показываются как warning или error по правилу критичности.

- графики;
- модальные окна;
- карточки исключений;

- длинные названия поставщиков;

## 30. Accessibility

Проверять:

- навигацию клавиатурой;
- видимый focus state;
- контраст текста;
- доступность таблиц;
- aria-label для icon buttons;
- отсутствие ловушек фокуса в модальных окнах;
- понятные тексты ошибок;
- невозможность подтверждения критичного действия без явного фокуса на кнопке.

## 31. Автоматизация UI-Тестов

### 23.1. Рекомендуемый Инструмент

Playwright.

Причины:

- бесплатный open-source;
- Apache-2.0;
- поддержка Chromium, Firefox, WebKit;
- удобен для E2E;
- поддерживает screenshots, traces, video;
- хорошо подходит для CI.

### 23.2. Структура Тестов

```text
tests/ui/
  smoke/
  forecast/
  promo/
  replenishment/
  fresh/
  exceptions/
  lifecycle/
  adjustments/
  publishing/
  procurement/
  capacity/
  diagnostics/
  supplier/
  true-inventory/
  store-tasks/
  workload/
  rbac/
  performance/
  visual/
```

### 23.3. Минимальный Набор Для CI

- smoke всех главных экранов;
- создание валидного промо;
- ошибка промо без SKU;
- корректировка прогноза;
- order proposal explanation;
- approval order;
- exception lifecycle;
- audit trail;
- RBAC viewer;
- публикация с ошибкой ERP/WMS.
- промо без места/мощности выкладки;
- supplier constraint;
- capacity overload;
- root cause card;
- store task completion.
