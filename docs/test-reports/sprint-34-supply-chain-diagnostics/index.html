Sprint 34 / Supply Chain Diagnostics

OPEN FNR - отчет по диагностике цепочки поставок

Тестируем, что система не ограничивается сигналом shortage/overstock, а объясняет вероятную первопричину, показывает доказательства, связывает forecast/order/promo/inbound объекты и позволяет создать exception из диагностического insight.

Что и зачем тестируем

Root Cause Card

Карточка должна показать причину late_delivery, confidence 0.88, симптом projected stock-out и рекомендуемое действие для supply exception.

Evidence Trail

Проверяем, что решение объяснимо: WMS late inbound, projected stock fact, forecast quality и связанные объекты доступны для аудита.

UI-тестирование по шагам

Шаг Что делаем Зачем Ожидаемый результат Полученный результат
1 Открываем Supply Chain Diagnostics. Проверить доступность диагностического рабочего места. Видны root cause и recommended action. Пройдено.
2 Проверяем таблицу insights. Планировщик должен видеть статус, affected store/SKU и symptom. Insight classified, root cause late_delivery, confidence 0.88. Пройдено.
3 Проверяем evidence rows. Root cause без доказательств нельзя использовать для операционного решения. WMS, Projected Stock и Forecast evidence присутствуют. Пройдено.
4 Проверяем действия Open evidence, Confirm root cause, Create exception. UI должен вести пользователя от анализа к управляемому процессному действию. Action panel отображается. Пройдено.

Тестирование бизнес-процессов

Процессный шаг Что делаем Почему Ожидаемый результат Факт
Collect evidence Собираем WMS, projected stock и forecast facts. Диагностика должна быть проверяемой, а не черным ящиком. BPMN содержит service task сбора evidence. Пройдено.
Classify root cause Классифицируем первопричину через DMN. Правила должны быть версионируемыми в Process Engine. DMN содержит late_delivery, forecast_underestimation, data_gap rules. Пройдено.
Review root cause card Пользователь подтверждает карточку причины. Перед exception нужна бизнес-валидация. BPMN user task и CMMN human task присутствуют. Пройдено.
Create exception from insight Создаем exception из insight с comment и evidence ids. Диагностика должна приводить к операционному действию. Viewer получает 403, Supply Chain Manager создает exception. Пройдено.
Audit trail Проверяем actor, role, comment и evidence list. Решение влияет на поставки и должно быть проверяемым. API возвращает audit payload. Пройдено.
