PN-11 Reporting and Superset payload

Дата: 2026-05-29. Цель: проверить, что Process Navigator умеет отдавать weekly report payload и Airflow digest может подготовить stakeholder-сообщение без хардкода host/port.

Аннотация теста

Мы тестируем reporting-слой отдельно от UI, потому что руководители и аудиторы могут получать еженедельный digest и Superset dataset без открытия карты. Такой способ проверки подтверждает, что данные Process Navigator пригодны для регулярной управленческой отчетности.

Скриншот контекста

Скриншот показывает UI-контекст, из которого формируется отчетная картина процесса.

Тесты reporting/API

Шаг Что делаем Зачем Ожидаемый результат Фактический результат
1 Вызываем `/process-navigator/reports/weekly` с `business_week` и `env`. Проверить контракт для weekly stakeholder report. Ответ содержит week, environment, summaries, root causes, SLA breaches и Superset dataset ref. Пройдено: backend contract test обновлен.
2 Строим Airflow digest request. Убедиться, что DAG не хардкодит host/port. Request содержит `OPEN_FNR_SERVICE_HOST` и `OPEN_FNR_API_PORT` как env-var references. Пройдено.
3 Строим stakeholder message. Проверить, что digest сохраняет root causes, SLA breaches и Superset dataset ref. Message пригоден для notification routing из Supplement 1 section K. Пройдено.

Тесты бизнес-процессов

Процесс Что проверяем Почему Результат
Weekly process health digest Сбор root causes и SLA breaches за неделю. Управленческая команда должна видеть системные причины задержек и блокировок. Готово на contract/skeleton уровне.
Superset process alert history Стабильный dataset ref `process_alert_history`. BI-слой должен строиться на стабильном имени датасета без URL-хардкода. Готово.
