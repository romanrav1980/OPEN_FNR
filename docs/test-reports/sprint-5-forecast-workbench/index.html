OPEN FNR / Sprint 5 / Forecast Workbench V1

Отчёт по UI-тестированию и тестированию бизнес-процессов

Отчёт фиксирует тестовый цикл Sprint 5: рабочий просмотр прогноза, фильтры, fact vs forecast panel и процесс review anomalies.

Аннотация теста

Мы тестируем Forecast Workbench V1, потому что Forecast Planner должен видеть прогноз не как техническую таблицу, а как управляемый рабочий экран. Метод проверки объединяет API-фильтры, empty state, UI build, screenshot и процессные артефакты review. Так мы подтверждаем, что пользовательский сценарий анализа прогноза уже имеет контракт и трассируемый бизнес-процесс.

UI-тестирование

Шаг Что делаем Зачем Почему именно так Ожидаемый результат Фактический результат
1 Открываем Forecast Workbench. Проверить основной рабочий сценарий Forecast Planner. Workbench должен быть первым экраном анализа прогноза. Блок Forecast Workbench отображается. Отображается.
2 Проверяем фильтры Date, Store, SKU, Category. Пользователь должен задавать срез анализа. Фильтры являются критичным UX-контрактом для больших объёмов данных. Фильтры видны и помещаются в layout. Видны.
3 Проверяем fact vs forecast panel. Показать отличие факта от прогноза визуально. График нужен для быстрых проверок аномалий. Chart panel отображается и не перекрывает таблицу. Отображается.
4 Проверяем таблицу прогноза. Дать точные строки для SKU-store-date drill-down. Таблица остаётся главным инструментом операционного анализа. Видны date, store, SKU, regular, total, flag. Видны.
