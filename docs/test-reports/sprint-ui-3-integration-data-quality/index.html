UI-3: Integration And Data Quality UI

Annotation. We test whether a data operator can see source readiness, DQ blockers, retry plan, reconciliation keys and downstream blockers from the UI. This test protects the operational flow that prevents bad source data from entering forecast, replenishment and publication.

Business Process Test Walkthrough

ProcessWhat We DoWhyExpected ResultActual Result
Source blocker recovery Check source readiness rows, owner, blocker count and recovery action. Operator must know who acts and what must be rerun. Readiness table is visible. Passed by static UI test.
Idempotent retry Check retry strategy, idempotency key, attempts and next action. Retries must not duplicate clean canonical rows. Retry table is visible. Passed by static UI test.
Reconciliation Check reconciliation keys and downstream blockers. Forecast and replenishment must stay blocked while critical sources are inconsistent. Reconciliation table is visible. Passed by static UI test.
DQ waiver or rerun Check DQ incident panel, waiver/rerun/export actions and publication blocker text. Waivers are high-risk and must be role-controlled and auditable. DQ action panel is visible. Passed by static UI test.
