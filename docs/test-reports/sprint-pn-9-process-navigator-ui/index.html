PN-9 Process Navigator UI - отчет по UI и бизнес-процессам

Дата: 2026-05-29. Контур: локальная сборка frontend. Цель: проверить, что карта бизнес-процессов показывает новые runtime-слои Process Navigator и содержит help-сноски с трассировкой к ТЗ и бизнес-процессам.

Аннотация теста

Мы тестируем Process Navigator как рабочее место операционного контроля BPMN-процессов. Такой способ проверки выбран потому, что пользователь должен видеть не только статус процесса, но и причину статуса: соответствие BPMN-модели, производительность, версии, инфраструктурные зависимости и причинно-следственные алерты.

Скриншот

Скриншот сделан из production-сборки Vite по маршруту #/process-navigator. API-запросы в file-mode ожидаемо уходят в fallback, что проверяет деградированное состояние UI без падения интерфейса.

Пошаговая проверка UI

Шаг Что делаем Зачем Ожидаемый результат Фактический результат
1 Открываем маршрут Process Navigator. Проверить, что рабочее место доступно после сборки. Раздел карты процессов отображается без runtime-ошибок. Пройдено: сборка Vite успешна, screenshot создан.
2 Проверяем semantic zoom Z0-Z4. Подтвердить навигацию от домена до BPMN-деталей. Кнопки имеют состояние выбора и доступны с клавиатуры. Пройдено: элементы сохранены, добавлена help-сноска.
3 Проверяем выбор BPMN-процесса. Убедиться, что detail-panel привязан к выбранному процессу. Выбор процесса управляет drilldown, метриками, версиями и алертами. Пройдено: добавлены fetch-контракты для drilldown, conformance, performance, versions.
4 Проверяем карточки conformance, P95 cycle time, versions, infrastructure risk. Показать пользователю здоровье процесса не одной лампочкой, а объяснимыми измерениями. Карточки видны, не ломают layout и имеют справочные ссылки. Пройдено: карточки добавлены, TypeScript build успешен.
5 Проверяем таблицу алертов и причинную цепочку. Отделить корневую причину от каскадных последствий. В таблице есть колонка Cause с root/cascade и цепочкой alert keys. Пройдено: колонка Cause добавлена.

Проверка бизнес-процессов

Процесс Что проверяем Почему это важно Ожидаемый результат Фактический результат
Forecast review process Conformance summary и ссылка на BPMN artifact. Нельзя выпускать прогноз, если обязательное согласование обойдено. Пользователь видит score, skipped steps и unexpected sequence. UI готов к приему backend-метрик.
Replenishment approval process P95 cycle time, rework и SLA-смысл метрики. Задержка согласования заказа влияет на service level и availability. Пользователь видит риск превышения SLA в detail-panel. UI карточка performance добавлена.
Process version governance Current version, active versions, stuck instances. Старые версии BPMN не должны скрываться за общим статусом процесса. Пользователь видит breakdown по версиям. Version breakdown добавлен.
Incident correlation Root/cascade chain в алертах. Операционная команда должна устранять upstream-причину, а не симптомы. Алерт показывает root/cascade и цепочку причин. Колонка Cause и help-сноска добавлены.
