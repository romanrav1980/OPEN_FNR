OPEN FNR / Sprint 4 / Regular Forecast Baseline

Отчёт по UI-тестированию и тестированию бизнес-процессов

Отчёт фиксирует тестовый цикл Sprint 4: первый регулярный baseline forecast, WAPE/Bias, forecast version API и процесс публикации прогноза.

Аннотация теста

Мы тестируем baseline forecast, потому что это первая версия прогноза, которую можно показать бизнесу и дальше сравнивать с ML-моделью. Метод проверки объединяет формулы метрик, API latest forecast, процессные артефакты и UI screenshot. Такой способ нужен, чтобы убедиться: прогноз воспроизводим, метрики считаются корректно, а публикация управляется правилами, а не ручным обходом.

UI-тестирование

Шаг Что делаем Зачем Почему именно так Ожидаемый результат Фактический результат
1 Открываем Dev Control Tower. Проверить, что прогноз встроен в общий operational UI. Бизнесу нужен путь от данных и DQ к прогнозу на одном экране. Страница отображается без ошибок. Отображается.
2 Проверяем карточку forecast version. Убедиться, что пользователь видит модель, data version, feature version и горизонт. Прогноз должен быть воспроизводим и трассируем. Видна версия regular-baseline-20260528-001. Видна.
3 Проверяем WAPE/Bias. Показать качество baseline до ML-улучшений. WAPE зафиксирована как основная метрика приёмки. Видны WAPE 18.4% и Bias -1.2%. Видны.
4 Проверяем forecast table. Убедиться, что строки прогноза доступны для read-only review. Это основа будущего Forecast Workbench. Видны date, store, SKU, regular, total, quality flag. Видны.

Тестирование бизнес-процессов

Процесс Шаг Что делаем Зачем Ожидаемый результат Фактический результат
regular_forecast_run_process 1 Стартуем процесс после публикации feature version. Forecast должен использовать утверждённый feature mart. BPMN содержит start event Feature version published. Подтверждено XML-тестом.
regular_forecast_run_process 2 Считаем baseline forecast. Получить первый регулярный прогноз без промо. BPMN содержит Score regular baseline. Подтверждено XML-тестом.
regular_forecast_run_process 3 Валидируем WAPE и Bias. Не публиковать прогноз без контроля качества. BPMN содержит Validate WAPE and Bias. Подтверждено XML-тестом.
forecast_publish_eligibility_decision 1 Проверяем DMN eligibility. Публикация должна зависеть от WAPE, Bias и blocking DQ. DMN содержит decisionTable publish_eligible. Подтверждено XML-тестом.
forecast_run_failure_case 1 Проверяем CMMN case для сбоя run. При плохих метриках нужен triage или approval baseline publication. CMMN содержит triage и approval tasks. Подтверждено XML-тестом.
