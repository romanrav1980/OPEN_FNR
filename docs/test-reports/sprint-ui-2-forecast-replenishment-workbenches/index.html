UI-2: Forecast And Replenishment Workbenches

Annotation. We test the planner UI path across forecast review, promo uplift, projected stock, order proposal, replenishment approval, exception handling and manual adjustments. This foundation gate proves that the screens, API contracts, audit/process context and accessible section labels exist before the broader Playwright E2E suite in UI-5.

Business Processes

ProcessWhat We DoWhyExpected ResultActual Result
Forecast review Check Forecast Workbench, KPI/forecast context and baseline separation. The planner must see the forecast before publication and understand manual adjustment impact. Screen and process markers exist. Passed by static UI test.
Promo uplift Check Promo Workbench, required promo fields, reference promos and regular/uplift/total split. Promo must not be forecasted without SKU, price, discount, dates, stores and display attributes. Required-field and uplift evidence exist. Passed by static UI test.
Demand projection Check inventory projection: stock, demand, open orders, in-transit and safety threshold. Ordering must use future demand projection, not only sales forecast. Projection panel and stock-out warning exist. Passed by static UI test.
Order proposal approval Check Order Proposal V1 and Replenishment Workbench with adjustment/audit context. The planner must see original proposal, final order, change reason and audit trail. UI shows adjustment, approval and audit trail. Passed by static UI test.
