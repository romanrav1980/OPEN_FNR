OPEN FNR / Sprint 3 / Feature Mart

Отчёт по UI-тестированию и тестированию бизнес-процессов

Отчёт фиксирует тестовый цикл Sprint 3: активная матрица, версионирование feature mart, point-in-time признаки и процесс публикации версии признаков.

Аннотация теста

Мы тестируем Feature Mart Foundation, потому что это слой, на котором будет построен первый регулярный прогноз. Метод проверки объединяет API-тесты, data rules, process artifact tests и UI screenshot. Такой подход подтверждает, что матрица исключает неактивные сущности, признаки не допускают leakage, а процесс публикации версии признаков управляется через BPMN/DMN/CMMN.

UI-тестирование

Шаг Что делаем Зачем Почему именно так Ожидаемый результат Фактический результат
1 Открываем Dev Control Tower. Проверить доступность общего рабочего экрана. Feature Mart должен быть виден рядом с ingestion и DQ. Страница отображается без ошибок. Отображается.
2 Проверяем Feature Mart Status. Убедиться, что пользователь видит версию признаков и статус сборки. Перед baseline forecast важно понимать, какая feature version опубликована. Видны versions, status, active pairs, feature count, quality. Видны.
3 Проверяем карточки Active Matrix и Feature Groups. Показать бизнес-смысл feature mart, а не только технический статус. Пользователь должен видеть исключение закрытых магазинов и inactive SKU. Карточки объясняют active matrix и point-in-time feature groups. Карточки отображаются.
4 Проверяем failed partition status. Убедиться, что ошибка сборки видима в UI. Проблемная партиция должна приводить к incident case, а не теряться. Версия со статусом failed выделена в таблице. Отображается.

Тестирование бизнес-процессов

Процесс Шаг Что делаем Зачем Ожидаемый результат Фактический результат
feature_build_process 1 Стартуем процесс после принятия DQ. Feature build должен начинаться только после quality gate. BPMN содержит start event DQ accepted. Подтверждено XML-тестом.
feature_build_process 2 Собираем active matrix. Исключить закрытые магазины, inactive SKU и невалидный ассортимент. BPMN содержит Build active matrix. Подтверждено XML-тестом.
feature_build_process 3 Собираем и валидируем feature mart. Не допустить leakage и неверные row counts до прогноза. BPMN содержит Build feature mart и Validate feature mart. Подтверждено XML-тестом.
feature_build_process 4 Публикуем валидированную версию. Forecast должен ссылаться на воспроизводимую feature version. BPMN содержит Publish feature version. Подтверждено XML-тестом.
active_matrix_inclusion_decision 1 Проверяем DMN-решение включения пары store x SKU. Правило active matrix должно быть управляемым, а не hardcode. DMN содержит decisionTable include_pair. Подтверждено XML-тестом.
feature_build_incident_case 1 Проверяем CMMN case для failed partition. Ошибки сборки требуют triage, rebuild или fallback approval. CMMN содержит triage и approve fallback tasks. Подтверждено XML-тестом.
